# Инструкция по сбору данных Wordstat

**Файл для заполнения:** `WORDSTAT_MASTER_TEMPLATE.csv` — 200 строк запросов
по 20 нишам, разделитель `;`.

**Время:** 3–4 часа на все 20 ниш при работе по порядку.
**Инструмент:** wordstat.yandex.ru (нужна авторизация в Яндексе).

---

## Почему это главный приоритет этапа

Весь рейтинг ниш построен на структурных признаках товара. Из структуры
можно вывести, **защищён ли товар от маркетплейса** и **можно ли продать его
без закупки**. Из структуры **нельзя** вывести, есть ли покупатели.

Ниша может быть идеально устроена и иметь 40 запросов в месяц по стране.
Этот замер — единственный способ узнать, какая именно.

---

## Принцип: кластер, а не один запрос

Один ключевой запрос — не показатель размера ниши. Он показывает частотность
одной формулировки, а покупатели формулируют по-разному.

```
НИША
├── CORE     основной запрос           «упаковочное оборудование»
├── BUY      + купить                  коммерческое намерение
├── PRICE    + цена                    стадия выбора
├── ORDER    + на заказ                наша модель работы
├── DELIV    + с доставкой             готовность к удалённой покупке
├── WHOLE    + оптом                   B2B-сегмент
├── B2B      + отраслевой модификатор  «для производства», «для кфх»
├── PRO      + профессиональный        проф-сегмент против бытового
├── ALT      альтернативные названия   «запайщик пакетов», «стрейч машина»
└── PROBLEM  проблемный запрос         информационный трафик
```

**Размер ниши = сумма коммерческих групп** (BUY + PRICE + ORDER + DELIV + WHOLE + B2B),
а не частотность CORE. CORE почти всегда завышен: в него попадают
информационные и навигационные запросы.

---

## Порядок работы

### Шаг 1. Настройка (5 минут, один раз)

1. Регион: сначала **Россия** — для оценки размера ниши.
2. Затем два города теста — для оценки локального спроса.
   Рекомендую взять **один миллионник** и **один город 300–700 тыс.**:
   разница между ними показывает, где меньше конкуренции при живом спросе.
3. Тип устройства: все.

### Шаг 2. Замер по нишам, строго по приоритету

Ниши в шаблоне уже отсортированы по валидированному рейтингу.
Идите сверху вниз и **не перескакивайте**: если первые пять ниш провалят порог,
остальные 15 всё равно нужно замерять, но приоритет теста уже будет ясен.

Для каждой строки заполните:

| Столбец | Что вносить |
|---|---|
| `pokazov_mes_RF` | Частотность по России, широкое соответствие |
| `pokazov_mes_gorod1` | Частотность по миллионнику |
| `pokazov_mes_gorod2` | Частотность по среднему городу |
| `dinamika_12mes_pct` | Изменение за 12 месяцев, % (вкладка «История запросов») |
| `dinamika_24mes_pct` | Изменение за 24 месяца, % |
| `trend` | рост / стабильно / падение |
| `pik_sezona` | Месяц максимума |
| `proval_sezona` | Месяц минимума |
| `top3_regiona` | Три региона с наибольшей концентрацией |
| `data_zamera` | Дата — обязательно, цифры устаревают |

### Шаг 3. Строка PROBLEM — заполняется вручную

В шаблоне она оставлена как `<проблема, которую решает>`. Впишите реальный
проблемный запрос покупателя. Примеры:

| Ниша | Проблемный запрос |
|---|---|
| Водоочистка | «почему из скважины идёт рыжая вода» |
| Сублимация | «как начать печатать на футболках» |
| Складская техника | «не поднимается рохля что делать» |
| Мебель HoReCa | «сколько столов нужно на 40 посадочных мест» |

Проблемные запросы — самый дешёвый трафик и лучший вход в диалог.
Если их частотность выше коммерческих, стратегия объявления меняется:
продавать нужно через решение проблемы, а не через товар.

## Пороги решения

**Заданы до сбора.** Это защита от подгонки трактовки под желаемое.

### Порог 1. Размер (сумма коммерческих групп, РФ, показов/мес)

| Сумма | Решение |
|---|---|
| < 300 | **Ниша закрывается.** Спроса нет |
| 300 – 1 000 | Только при чеке > 50 тыс ₽ и слабом поле. Иначе в резерв |
| 1 000 – 5 000 | **Рабочая зона** для нашей модели |
| 5 000 – 20 000 | Хорошо, но проверить конкуренцию особенно тщательно |
| > 20 000 | Осторожно: поле вероятно занято, идёт ценовая война |

### Порог 2. Доля коммерческих запросов

```
Доля = сумма коммерческих групп / (сумма коммерческих + CORE + PROBLEM)
```

| Доля | Трактовка |
|---|---|
| > 40% | Отличное коммерческое намерение |
| 20–40% | Норма |
| < 20% | Люди интересуются, но не покупают. Осторожно |

### Порог 3. Динамика

| dinamika_12mes | Решение |
|---|---|
| Рост > 15% | Плюс к рейтингу |
| −15% … +15% | Нейтрально |
| Падение > 15% два года подряд | Понизить нишу независимо от размера |

### Порог 4. Локальная концентрация

```
Отношение = показов в городе-миллионнике / показов по РФ
```

| Отношение | Трактовка |
|---|---|
| > 15% | Спрос сконцентрирован в столицах — конкуренция там же |
| 5–15% | Нормальное распределение |
| < 5% | **Спрос размазан по регионам** — нужна работа с доставкой, а не с одним городом |

Последний случай особенно важен для ниши «оборудование для КФХ»: она заранее
помечена как географически рассеянная, и замер это подтвердит или опровергнет.

## Типовые ошибки замера

| Ошибка | Последствие | Как избежать |
|---|---|---|
| Считать CORE как размер ниши | Завышение в 3–10 раз | Считать только коммерческие группы |
| Не проверять регион | Ниша выглядит большой, а в вашем городе её нет | Обязательно два города |
| Замер в мёртвый сезон | Ложный отрицательный результат | Смотреть историю за 12 месяцев, а не текущий месяц |
| Игнорировать альтернативные названия | Занижение в 2–3 раза | Строка ALT обязательна |
| Смотреть широкое соответствие без уточнения | В выборку попадает мусор | Проверять операторами `"..."` спорные запросы |
| Не записывать дату | Через месяц данные несопоставимы | Столбец `data_zamera` обязателен |

## После заполнения

1. Посчитать сумму коммерческих групп по каждой нише.
2. Применить пороги 1–4, отметить закрытые ниши.
3. Обновить критерий «устойчивость спроса» в
   `../05_SCORING/build_scoring.py` по фактическим данным.
4. Перезапустить `../05_SCORING/build_scoring.py` и `build_validation.py`.
5. Сравнить новый рейтинг с текущим — расхождения записать в
   `../09_FINAL_REPORT/QUALITY_CONTROL.md`.
6. Занести источник в `../10_SOURCES/ALL_SOURCES.csv` с датой замера.

**Сохраните заполненный файл отдельной копией с датой** —
он станет первым в проекте набором реальных данных, и с ним нужно
будет сравнивать замеры через квартал.

## Чего этот замер НЕ покажет

| Не покажет | Почему | Чем закрывается |
|---|---|---|
| Спрос на Авито | Wordstat — это Яндекс, а не Авито | Протокол `../03_DATA_COLLECTION/AVITO/MANUAL_ANALYSIS_PROTOCOL.md` |
| Платёжеспособность спроса | Частотность не равна деньгам | Только рыночный тест |
| B2B-спрос целиком | Закупщики часто ищут не через поиск, а по контактам и в отраслевых каналах | Прямой обзвон, отраслевые площадки |
| Конверсию в сделку | Это метрика теста, а не замера | `../07_AVITO_TEST_STRATEGY/METRICS.md` |

**Особая оговорка про B2B.** В валидированном рейтинге восемь ниш из десяти —
B2B. Wordstat систематически **занижает** B2B-спрос: снабженец ищет поставщика
не поисковым запросом, а по рекомендации или в отраслевом каталоге.

Поэтому для B2B-ниш порог 1 применяется мягче: **сумма от 300 показов/мес
уже считается рабочей**, если у ниши высокий чек и слабое поле.
Для B2C-ниш порог остаётся жёстким.
