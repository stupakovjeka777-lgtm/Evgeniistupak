# Архитектура рабочего пространства

Документ описывает, как устроено хранилище исследования: где что лежит, как данные
движутся от источника к выводу и по каким правилам это работает. Содержательные выводы
здесь не хранятся.

---

## 1. Принцип устройства

Папки пронумерованы в порядке работы. Номер — это не тема, а очередь:
данные всегда движутся от меньшего номера к большему.

```
00-brief         ← зачем исследуем и какое решение принимаем
   ↓
01-desk-research  02-competitors  03-audience     ← сбор фактов
   ↓                    ↓               ↓
        04-pricing  ←───┴───────────────┘          ← считаем деньги
             ↓
        05-channels                                ← где брать клиента
             ↓
        06-findings                                ← ответ и решение

sources/   ← реестр ссылок, на который ссылается любая цифра из 01–06
data/      ← сырьё и обработанные таблицы, доказательная база
templates/ ← заготовки для повторяющихся артефактов
```

Обратной связи нет только на бумаге: если фаза 4 опровергает допущение фазы 2,
правится фаза 2, а не игнорируется фаза 4.

## 3. Поток данных

```
источник (сайт, выгрузка, интервью)
   │
   ├─→ data/raw/2026-08-31_источник_суть.csv       копия как есть, не трогаем
   │
   ├─→ sources/sources.csv                          строка S7: ссылка, дата, надёжность
   │
   ├─→ data/clean/2026-08-31_источник_суть.csv      очищенная таблица, если нужна
   │
   └─→ 01–05/*.md                                   цифра в таблице + ссылка (S7)
            │
            └─→ 06-findings/summary.md              вывод со ссылкой на цифру
```

Правило проверяемости: от любого числа в `06-findings/` можно за два шага дойти
до строки в `sources/sources.csv` и до файла в `data/raw/`. Если нельзя — число
не готово к использованию в решении.

## 4. Соглашения

### Имена файлов

```
YYYY-MM-DD_источник_суть.расширение
2026-08-31_avito_ceny-divany-msk.csv
2026-08-31_rosstat_roznichnyj-tovarooborot.xlsx
```

Только латиница, нижний регистр, дефисы вместо пробелов. Дата — дата сбора данных,
а не дата, к которой данные относятся; период данных указывается внутри файла
и в колонке `data_period` реестра источников.

### Идентификаторы

| Префикс | Что нумерует | Где живёт |
|---|---|---|
| `S1, S2, …` | Источники | `sources/sources.csv` |
| `H1, H2, …` | Гипотезы | `00-brief/hypotheses.md` |
| `C1, C2, …` | Конкуренты | `02-competitors/competitors.csv` |
| `J1, J2, …` | Задачи клиента (JTBD) | `03-audience/jtbd.md` |
| `P1, P2, …` | Боли | `03-audience/jtbd.md` |

Идентификаторы не переиспользуются: если источник удалён, его номер остаётся занятым.

### Цифры в таблицах

- Единицы и валюта — в заголовке колонки: `Цена, ₽`, а не `12 000 руб.` в ячейках.
- Оценка помечается явно, с расчётом: `~15 млрд ₽ (оценка: 3 млн заказов × 5 000 ₽)`.
- У каждой цифры — колонка `Источник (ID)`.
- Для распределений указывается медиана и размер выборки: одна дорогая позиция ломает среднее.

### Уверенность

| Уровень | Основание |
|---|---|
| Высокая | Госстатистика, отчётность по ИНН, собственные измеренные данные |
| Средняя | Отраслевые ассоциации, аналитика с описанной методологией, 2+ согласованных источника |
| Низкая | СМИ без первоисточника, пресс-релизы, экспертные мнения без данных |

## 5. Запреты

Нарушение любого пункта делает исследование непроверяемым.

- **Не редактировать `data/raw/`.** Исправления — только в `data/clean/`.
- **Не коммитить персональные данные респондентов:** ФИО, телефоны, адреса, переписку.
  Формат ссылки на респондента: «клиент №3, сегмент А».
- **Не коммитить учётные данные и токены**, в том числе внутри выгрузок из личных кабинетов.
- **Не хранить в репозитории файлы больше 50 МБ** — ссылка и описание вместо файла.
- **Не ставить цифру без источника.** Черновая гипотеза помечается как `?` до подтверждения.

---

## 6. Как расширять

- Новый повторяющийся артефакт → шаблон в `templates/`, а не копипаст между папками.
- Новый блок исследования → папка с двузначным номером в порядке работы + строка
  в разделе «Артефакты» в `PROJECT_PLAN.md`.
- Смена правил из этого файла → запись в журнале решений `PROJECT_PLAN.md` с основанием.
